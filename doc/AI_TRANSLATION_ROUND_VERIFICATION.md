## 1. 计时口径（验收 1）

**根因**：`phaseDoneAfter()` 返回的是「距任务开始」的累计秒数，卡片却把它印在该阶段名下。
在你那次运行里就是 `已识别 0:50 / 已翻译 4:41 / 已渲染 4:44` —— 4:41 里含着 OCR 的 50 秒，
三行相加不等 4:44。

**修法**：逐段相减（识别 = ocrDone − start；翻译 = translatedDone − ocrDone；渲染 = renderDone − translatedDone），
并在 `_processGroup` 的两个回调处补齐 `requestSentAt` / `firstResponseAt` 两个只有管线自己看得到的时刻。

**验收对照**（同一次运行）：

| | 修复前 | 修复后 |
| :-- | :-- | :-- |
| 已识别 | 0:50 | 0:50 |
| 已翻译 | **4:41（含 OCR）** | **3:51** |
| 已渲染 | 4:44 | 0:03 |
| 三者相加 | 5:35 ≠ 4:44 ✗ | **4:44 ✓** |

**可核对的时间戳**：每任务一行日志

```
Pre-translation  PhaseTimeline pages=37 start=15:08:12 ocrStart=… ocrDone=15:09:02
  reqSent=15:09:03 firstResp=15:10:51 done=15:12:56 ocr=50.0s translate=231.0s render=3.0s sum=284.0s total=284.0s
```

**测试**：`test/pre_translation_phase_finish_test.dart` —— 用你那次运行的真实秒数作夹具，
并断言 `recognition + translation + render == total`，另含未完成阶段 sum 必须为 null、时钟回拨、摘要与实时同口径等 6 例。

## 2. 实时看板（验收 2）

**根因（有日志证据）**：请求 15:09:03 发出、首个响应 15:10:51 到达 —— **108 秒**里
卡片没有任何可变的东西（分组的计数只在批次落地时移动），日志同一窗口也全是 OCR 行。
**不是模型慢，是没有上报通道。**

**修法**：活动对象新增「当前章节 / 页范围 / 最近响应 / 最近错误 / 等待时长」，
卡片渲染四行（值进文本出，纯函数 `taskBoardLinesOf` 便于断言）：

```
当前阶段：翻译中 · 当前：Ch 2 · 第 12–17 页
正在等待翻译接口响应：1:48（本组 6 页在途）      ← 等待期每秒跳动
mimo-v2.5 · 本次请求未发送任何 reasoning/思考参数：应用只发送模型名、系统提示词与文本。
最近一次响应：1:00        （或「最近一次错误：<原文>」，错误色）
```

**关于 reasoning**：应用侧**不发送**任何 reasoning/采样参数（`llm_translator.dart` 的载荷只有
`{model, messages[system,user]}`），因此看板只如实声明"未发送"，不臆断服务端行为。

**首屏**：`PreTranslationTaskManager.start()` 在返回前就 `currentTasks.insert(0, task)` +
`notifyListeners()`，调用方同时弹 toast（"Pre-translation started"）⇒ t=0 即有反馈；
看板四行随首批 chunk 交给 worker（数秒内）出现，此后按卡片刷新率逐秒跳动。

**测试**：`test/tasks_board_lines_test.dart`（走真实数据路径：任务+活动 → `snapshot` → 四行），
`test/pre_translation_phase_finish_test.dart` 覆盖 `waitingFor` 的四个边界。

## 3. 智能清除黑色色块（验收 3）

**复现**（用你缓存里的原图与渲染图逐页对比，37 对）：

| 页 | 现象 |
| :-- | :-- |
| 31 | 白字黑底「クソッ」擦完留下一条深色拖影 |
| 35 | 黑色爱心连同网点被抹成一块黑斑 |

修复前后对比图：`<本地取证目录>\page35_x1164_y136.png` 等（左原图 / 右渲染）。

**根因**：深底或中间调窗口上，「离环形背景更远的那一类算文字」选中的是**亮的那一类**，
而那片区域里亮的是**纸面与描边**，不是字形 ⇒ 近半个矩形被擦掉、填充把深色拖过来。
台账 `erased=N rolled_back=0` 因此完全合理：**回滚没失灵，是擦除在正确地做错事**。

**修法**：新增「亮团块」判据，且**只在文字类为亮时**生效 ——

| 用例 | 最大亮连通域 |
| :-- | :-- |
| 合法（黑气泡内三条细白笔画） | **360 px** |
| 出斑（31 页） | **3,216 px** |
| 出斑（35 页） | **63,604 px** |

阈值 `maxBrightComponentPixels = 2000`，落在实测空隙里；被拒的窗口**保持原像素**（宁可留原文，不留黑块）。

**一次失败的尝试，已回退并记录**：先用「掩膜覆盖率上限 0.35」做过，云端报 7 处失败 ——
合法的"贴页边密集标题"（覆盖 0.76）与"黑底白字"（0.47）同出斑窗口在覆盖率上重叠 ⇒ 判据错，
回退为行为不变的 0.85，并把这次测量与结论写在常量注释里。

**测试**：`test/inpaint_bright_blob_test.dart`（细白笔画仍擦、密集深字不受影响、大亮团块被拒且像素逐字节不变、阈值必须落在 360–3216 之间）。

## 4. 相邻气泡译文融合（验收 4）

**复现**（你那次运行的 store，逐条原文）：

| 页 | 存下来的块 | 问题 |
| :-- | :-- | :-- |
| 4 | `俺のだけど我慢してくれよ…` ／ `俺のだけどが母さんのヤ絶対触れね` | 同句被截断的第二份 |
| 9 | `求められたら絶対逆らえないっしょ.` ×2（框互相包含） | 逐字重复 |

两个重复块各自翻译、各自回填到自己的框 ⇒ 渲染出"串行/错乱"。

**根因**：拼接处判重用 `_iou > 0.5`。IoU 除以**并集**，所以"整条 vs 被裁掉一半"这种尺寸悬殊的同一条线
**恒小于 0.5** ⇒ 两份都留下。

**修法**：跨 tile 判重改用**包含度**（交集 ÷ 较小者）≥ 0.8 或 IoU > 0.5，且**保留更完整的那一份**（面积大者）。
阈值用你那次运行的真实框钉住：三对必须合并（包含度 1.00）、相邻两列必须保留（0.08）。

**没有乱动的地方（如实记录）**：另有 0.47 与 0.70 两对属于"同一气泡的两种识别变体"，
一个该并、一个该留，**几何分不开** ⇒ 阈值留在原处，把中间地带写进测试（`test/ocr_tile_stitch_test.dart`）。

**测试**：`test/ocr_tile_stitch_test.dart`（7 例，含上述全部真实坐标）。

## 6. 附带修好的两个观测缺陷（本轮顺带，均有测试）

1. **日志无法对页**：worker 每页行用的是**批内下标**，一章 37 页时 `page=3` 每批都指不同页 ——
   这正是此前"你的截图"与"我的日志"始终对不上的原因。现在每次 OCR 调用先打
   `OCR batch pages=31.jpg,32.jpg,…`（取缓存键末段，短且逐页唯一）。
2. **擦除台账看不出成因**：黑块有两种完全不同的成因（掩膜吃掉美术区 / 填充拖暗像素），
   台账原本两个都不记录。现在每次擦除带 `masks={x,y(bg=… text=… cover=…)}`。
